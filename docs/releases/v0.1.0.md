# TalentGraph AI v0.1.0

**Semantic talent search and candidate rediscovery — with measured retrieval quality.**

Search your talent pool the way recruiters think: *"senior Python backend
engineer in Berlin with Kubernetes experience"* — not `python AND berlin`.
Every result explains itself, and the retrieval quality is benchmarked with
real IR metrics instead of vibes.

Runs fully **keyless**: deterministic demo embeddings + rule-based query
parsing by default; OpenAI adapters behind the same interfaces when you
configure a key.

## Highlights

- **Hybrid retrieval, actually hybrid** — PostgreSQL full-text search + pgvector
  embeddings combined with Reciprocal Rank Fusion; SQLite BM25 + Python cosine
  for hermetic dev/tests.
- **Explainable ranking** — per-result "Why this result?" panel: lexical rank,
  cosine similarity, fusion score, reranker notes (including the geography
  boost), and the resume lines that matched, quoted.
- **Soft vs hard constraints** — constraints written in prose ("5+ years",
  "in Berlin") are transparent ranking signals; constraints you set as filters
  are strict SQL. Documented decision, benchmarked both ways (ADR 0003).
- **Measured quality** — a 24-query golden set with graded ground-truth
  labels; P@K / R@K / MRR / nDCG across four strategies. Hybrid + rerank:
  **P@10 0.779 · R@10 0.492 · MRR 0.958 · nDCG 0.785** on the seeded pool.
- **Talent rediscovery** — paste a JD → parsed requirements → ranked pool
  matches + explicit gaps.
- **200 synthetic profiles**, deterministic (seed=42), with alias variety
  ("K8s", "Postgres", "React.js") so lexical vs semantic differences are real.
- **Keyless demo embeddings** — deterministic, feature-hashed,
  taxonomy-canonicalized; the behavior is inspectable, not a black box.

## Quick start

```bash
git clone https://github.com/Nihal-MN/talentgraph-ai.git
cd talentgraph-ai
docker compose up --build -d
# open http://localhost:3400
```

First boot migrates, seeds 200 profiles, computes embeddings and runs the
benchmark. No API keys, no signup.

## Stack

Python 3.12 · FastAPI · SQLAlchemy 2 · Alembic · PostgreSQL 16 + pgvector
(HNSW) · Next.js 16 · React 19 · Tailwind 4 · pytest + Vitest ·
GitHub Actions (SQLite suite + PostgreSQL/pgvector suite + frontend + Docker).

## Verification

- 111 backend tests, green on **both SQLite and PostgreSQL + pgvector**
- 20 named retrieval evals (`pytest tests/evals`)
- 12 frontend tests · lint · typecheck · production build
- Docker stack verified: pgvector extension confirmed live in `/health`

## Honest limitations

- Live OpenAI paths (embeddings, LLM parsing) are adapter-complete and
  stub-tested; not run live in this repository (no key committed, obviously).
- No authentication — local demo by design (roadmap item #1).
- Synthetic evaluation measures retrieval *mechanics* reproducibly, not human
  relevance judgment — see `docs/EVALUATION.md`.
